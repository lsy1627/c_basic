# 动态内存

## 一、动态内存是什么

程序运行时向操作系统"临时租一块内存"来存数据，用完还回去。

1. **栈内存**：一般定义的变量都是在栈区获得内存，由系统自动分配和释放。
2. **堆内存**：通过 `malloc()`、`free()`、`calloc()`、`realloc()`，由用户手动分配和释放。

---

## 二、动态内存的作用

数组会在栈上提前分配内存，但是使用前并不知晓后续需要用到多少：使用的少于分配的则浪费了，若大于分配的则会出错。

因此会使用动态内存来装大小未知的东西。

---

## 三、动态内存函数

> 使用前必须 `#include <stdlib.h>`，否则编译器报隐式声明（C4013）甚至链接失败。

### 0. 三个分配函数的共同点

- **返回值**：申请成功返回该空间起始地址，申请失败返回 `NULL`。
- **为什么是 `void *`**：因为申请时不知道要存什么类型的数据，所以返回 `void *`，拿到返回值后需要**强转**成需要的类型。
- **必须检查**：申请可能失败（内存不足），不检查直接解引用就是访问非法地址。

### 1. `malloc()`

C 语言提供的动态内存开辟函数，向内存申请一块**连续可用**的空间，并返回指向该空间的指针。

- **原型**：`void *malloc(size_t _Size)`
- **参数**：`size_t` 表示无符号类型；`_Size` 表示申请分配的内存大小，单位为字节
- **返回值**：成功返回首地址，失败返回 `NULL`
- **注意**：分配到的内容是**未初始化的垃圾值**，必须自己初始化后才能使用

```c
int *num = (int*)malloc(10 * sizeof(int));
if(num == NULL){
    printf("gain failed!");
    return -1;
}
for(int i = 0; i < 10; i++)
    num[i] = 0;        // 必须自己初始化
```

### 2. `free()`

释放申请的动态内存空间。

- **原型**：`void free(void *_Memory)`
- **参数**：指向先前用 `malloc`、`calloc` 或 `realloc` 分配的内存块的指针
- **注意事项**：
  1. 使用完一定要记得 `free`，否则造成内存泄漏。
  2. `free` 之后一定要将指针置为空指针，防止野指针/悬垂指针。
     原因：`free` 只释放 `_Memory` 指向的那块空间，**指针变量本身不会被置空**。
  3. `free` **只能传原始指针**（`malloc` 系列返回的那个），不能传 `p+1`、`&p` 之类，否则是未定义行为。
  4. 同一块内存**不能重复 `free`**。

```c
free(num);
num = NULL;        // 释放后立刻置空
```

### 3. `calloc()`

功能类似 `malloc`，同样申请一块连续空间，但**参数形式和清零行为**不同。

- **原型**：`void *calloc(size_t _NumOfElements, size_t _SizeOfElements)`
- **参数**：`_NumOfElements` 元素个数；`_SizeOfElements` 单个元素大小
  （总大小 = 两者相乘）
- **返回值**：同 `malloc`

#### 与 `malloc()` 的区别

| | `malloc` | `calloc` |
|---|---|---|
| 参数形式 | `malloc(总字节数)` | `calloc(个数, 元素大小)` |
| 是否清零 | ❌ 垃圾值 | ✅ **自动全赋 0** |
| 额外检查 | 无 | 内部会检测乘法溢出 |

> 提示：结构体里的指针成员即使被 `calloc` 清成 `NULL`，用 `%s` 打印仍会崩溃，仍需手动赋值。

```c
int *a = (int*)malloc(10 * sizeof(int));    // 内容是垃圾值
int *b = (int*)calloc(10, sizeof(int));     // 内容全为 0，可以直接用
```

### 4. `realloc()`

让动态内存管理更加灵活：用于重新调整之前调用 `malloc` 或 `calloc` 所分配的内存块的大小，可以对动态开辟的内存进行大小调整。

- **原型**：`void *realloc(void *_Memory, size_t _NewSize)`
- **参数**：`_Memory` 是 `malloc`/`calloc` 分配得到的指针；`_NewSize` 是新大小，单位为字节
- **注意**：**只有 `realloc` 扩出来的部分不是 0**（`calloc` 独有的清零能力它没有）

#### 调整空间的几种情况

**情况 1：`new_size > old_size`（扩容）**

- 可能 A：**原地扩展**（地址不变）——原内存后面恰好有所需的空闲区
- 可能 B：**搬家**（地址改变）——后面没空间了，重新找一块区域，把旧内容复制过去，释放旧内存
- 可能 C：**失败**——返回 `NULL`，**原内存完好无损**

所以**不能直接** `xxx = realloc(xxx, ...)`：失败时会把唯一保存地址的变量覆盖成 `NULL`，既泄漏又野指针。

正确写法（先存临时变量，检查成功再替换）：

```c
int *tmp = (int*)realloc(num1, 20 * sizeof(int));
if(tmp == NULL){
    printf("realloc failed!");
    free(num);
    return -1;
}
num1 = tmp;                    // 成功才换指针

// 新扩出来的 10 个是垃圾值，必须先初始化
for(int i = 10; i < 20; i++)
    num1[i] = 0;
```

**情况 2：`new_size < old_size`（缩容）**

- 前 `new_size` 字节保留，超出部分被截断
- 指针通常不变（但标准不保证，别依赖）
- 用途：申请了 128 字节但只用了 12 字节，可以缩到刚好

**情况 3：`new_size == 0`**

- 多数实现相当于 `free` 并返回 `NULL`，但**少数实现行为不同**
- **结论：不要用 `realloc(p, 0)` 代替 `free(p)`**，想释放就写 `free`

## 四、内存泄漏

**没有使用 `free` 释放自己申请的动态内存，并且那块地址也已经丢失了，再也没办法找到它。**

会导致内存持续下降、运行速度变慢，长时间运行的程序甚至会崩溃。进程正常退出时系统会回收全部内存，所以**小程序往往测不出泄漏，别以为没报错就没事**。

### 常见的三种泄漏场景

1. **忘了调用 `free`** —— 最常见
2. **申请的指针被覆盖**（丢指针）—— 泄漏的地址再也找不到了
3. **只释放了外层、没释放内层** —— 例如结构体里每个成员单独 `malloc` 的，必须先逐个释放成员，再释放结构体数组本身

```c
void destroy(Student *s, int n){
    for(int i = 0; i < n; i++)
        free(s[i].name);   // ① 先释放嵌套的内层指针
    free(s);               // ② 再释放外层数组
}                           // 漏掉 ① 就是泄漏 n*20 字节
```

### 与悬垂指针的区别

| | 内存泄漏 | 悬垂指针（use after free） |
|---|---|---|
| 问题 | 没释放，内存被占着 | 释放了但还在用 |
| 后果 | 内存耗尽 | 数据错乱、崩溃、安全漏洞 |
| 修法 | 补 `free` | `free(p); p = NULL;` |

### 避免泄漏的四条铁律

1. **谁申请谁释放**；函数内申请的必须返回出去，并在注释里写明由调用者 `free`
2. **释放必须传原始指针**（`malloc` 返回的那个，不能是它的偏移）
3. **`free` 之后立刻置 `NULL`**
4. **嵌套申请时，先内后外释放**

> 注意：**不是所有返回指针的函数都需要调用者 `free`**。如果函数返回的是指向已有内存的内部指针（如指向 `src` 中间位置的指针），`free` 它反而是错误。
